先分清三种“保护”

表中 ①②③ 三行对应下面三件事。它们层层递进，不能用前一件去证明后一件。“任何人都拿不到明文”对应第 ③ 件；“加密落盘了”只证明了第 ① 件。

① at-rest离线 / 落盘保护

只拿到盘上那段密文，还不足以还原私钥。防的是偷盘、偷备份。

② in-use运行时 / 在用保护

做密码运算的那一刻，私钥对设定的对手不可见。如果声称连特权主机软件都能挡，那 OS root 也必须读不到。

③ non-extractable芯片内生成且不可导出

私钥在安全芯片 / HSM 内生成，整个生命周期（含备份、恢复、迁移）里从不以明文离开。这才是“私钥永不出硬件”。

两条容易混的：“接口不可导出”不等于“硬件不可提取”（某条命令拒绝导出，只说明那个接口不给）；“芯片内不可导出”不等于“芯片内生成”（Cisco 的 SUDI 是后端 HSM 生成后加密注入芯片的）。

读表时要注意

按对手、证书来源与密钥用途分格看。受限配置管理员、掌握底层的 OS root、厂商维护工程师是不同的对手；设备自生成、从外部导入、厂商注入的证书风险也不同（导入的私钥在设备外存在过，可能已有副本）。Cisco 还要分“身份私钥”和“数据面对称密钥”两头：前者有硬件保管的强依据，后者在默认模式下 Controller 就持有。

FortiGate：“主口令封进 TPM”不等于“私钥拿不到”

7.6.1 起主口令由设备随机生成、经 TPM primary key 封存、无人知道。这把离线 / 落盘防护做扎实了：偷盘、偷备份解不开，也堵了 7.4 上“带着主口令去别处克隆”的路。但它管不到已登录的管理员：

  • 导出的私钥由“证书自身的私钥密码”加密，和主口令是两层、互不相干。这个密码留空时由设备随机生成、无人知道，看上去导出的是打不开的密文。
  • 但管理员可以把这个密码改成自己知道的：set password <新> 会让 FortiOS 用新密码重新加密同一把私钥，之后导出或 show 出来的私钥就能解开。开不开 PDE、有没有 TPM 都一样。
  • 已经封掉的老路：unset password 取明文 6.0 起已封（FG-IR-19-134）；GUI 下载只给公钥。
  • 没有“不可导出”开关：config vpn certificate local 下没有 TPM 或 non-exportable 选项。真正封在 TPM 里、不可导出的只有工厂证书（7.4.8+、200G 起），而它禁用于 IPsec。

真机实证

FortiGate-VM 7.6.8（build 3744，EVE-NG/KVM）2026-11-19 · PDE 未开启
  1. execute vpn certificate local generate rsa TESTCSR 512 CN=pde-test.lab，不填密码。show full-configuration 显示 set password ENC …（设备随机生成的私钥密码）和 -----BEGIN ENCRYPTED PRIVATE KEY-----（PKCS#8 加密存储）。试用授权只支持 512 位，与密码 / 导出机制无关。
  2. 取出这段私钥，用任意已知口令 openssl pkey：解不开（bad decrypt）。随机密码确实未知。
  3. 管理员执行 config vpn certificate local → edit TESTCSR → set password KnownPass123 → end，提交成功。
  4. openssl pkey -passin pass:KnownPass123：成功解开，解出的公钥模数与第 1 步 CSR 里的一致——是同一把私钥被重新加密，不是重新生成。用错口令仍是 bad decrypt。
  5. unset password 返回 Certificate 'TESTCSR' is not allowed to unset. Return code -14。这条路是封了的，但上面用的是 set，不需要它。

在另一台虚拟 TPM 已被 FortiOS 识别并初始化的 7.6.8 节点上重复，结果相同。试用授权下没有 private-data-encryption 开关，所以这一轮没有测到 PDE 开启状态。

FortiGate-VM 7.4.13（AWS PAYG，正式授权）2026-11-21 · PDE 已开启
  1. set private-data-encryption enable 开启成功：get system status 显示 Private Encryption: Enable，execute private-encryption-key sample 返回 HMAC。
  2. generate rsa PDEON 2048，不填密码：用已知口令解不开。
  3. set password KnownPass123 后，用该口令 openssl 解出明文；错口令失败；unset password 返回 -14。

结论：开启 PDE 不改变这条路径。7.6.1+ 与此的差别只是主口令改由设备随机生成，而主口令不参与证书自身密码的加解密，所以按机制同样成立；AWS 上的 7.6.8 没有直接跑。
